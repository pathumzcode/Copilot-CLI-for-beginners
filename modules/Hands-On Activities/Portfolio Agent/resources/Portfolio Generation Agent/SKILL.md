# Portfolio Generation Skill

## Purpose

This skill provides structured instructions for generating a professional, responsive personal portfolio website from verified CV or profile information.

The skill must ensure that portfolio content is accurate, professional, accessible, responsive, and based only on information provided by the user.

---

## Core Principles

Follow these principles throughout the portfolio-generation process:

1. Use the user's CV or verified profile information as the primary source.
2. Never invent personal, educational, professional, project, certification, technical, or achievement information.
3. Do not assume missing information.
4. Ask the user to verify extracted information before generating the portfolio.
5. Preserve existing project structure and functionality whenever possible.
6. Do not delete important files without user approval.
7. Prefer targeted changes instead of unnecessary rewrites.
8. Use clean, maintainable, and readable code.
9. Follow semantic HTML and accessibility best practices.
10. Ensure the website is responsive across desktop, tablet, and mobile devices.
11. Review all generated content before considering the portfolio complete.

---

## Workflow

Follow this workflow when generating a portfolio.

### Phase 1 - Analyze the CV

Analyze the provided CV and identify relevant information such as:

* Full name
* Professional title or introduction
* About/profile summary
* Education
* Technical skills
* Programming languages
* Frameworks and technologies
* Projects
* Work experience
* Internships
* Certifications
* Achievements
* Extra-curricular activities
* GitHub profile
* LinkedIn profile
* Other professional links
* Contact information

Do not add information that is not available in the CV.

After extracting the information, present it to the user for verification.

Do not begin portfolio generation until the user confirms that the extracted information is accurate.

---

### Phase 2 - Plan the Portfolio

After the CV information has been verified, create an implementation plan.

The plan should describe:

* Portfolio structure
* Required sections
* Technologies to be used
* Files to be created
* Files to be modified
* Design approach
* Navigation
* Responsive behavior
* Accessibility
* Images and visual elements
* Existing functionality that must be preserved

Do not make implementation changes until the user approves the plan.

---

### Phase 3 - Generate the Portfolio

After the user approves the implementation plan, generate the portfolio.

Create an appropriate structure based on the verified information.

Possible sections include:

* Home
* About
* Education
* Languages & Technical Skills
* Projects
* Certifications & Achievements
* Experience
* Extra-Curricular Activities
* GitHub
* LinkedIn
* Contact

Only create sections that are relevant to the information available.

Do not create empty sections containing placeholder or invented information.

---

## Design Requirements

The portfolio should have:

* A modern professional interface
* Clear visual hierarchy
* Consistent typography
* Appropriate spacing
* Responsive layouts
* Accessible navigation
* Clear call-to-action elements
* Professional color usage
* Appropriate images or visual elements
* Smooth and meaningful animations where appropriate
* Good readability across screen sizes

Avoid excessive animations, unnecessary visual effects, or design elements that reduce usability.

---

## Technical Requirements

Use clean and maintainable code.

### HTML

* Use semantic HTML elements.
* Maintain a logical document structure.
* Use appropriate headings.
* Provide meaningful `alt` text for images.
* Ensure links and buttons are clearly identifiable.

### CSS

* Use organized and maintainable styles.
* Create responsive layouts.
* Support desktop, tablet, and mobile screen sizes.
* Maintain consistent spacing, typography, and components.

### JavaScript

* Use JavaScript only where required.
* Keep functionality simple and maintainable.
* Avoid unnecessary dependencies.
* Ensure interactive features work correctly.

---

## Content Accuracy

Before finalizing the portfolio, verify:

* Names
* Dates
* Education
* Institutions
* Projects
* Skills
* Certifications
* Achievements
* Experience
* Professional links
* Contact information

All information must match the verified CV.

Never create:

* Fake projects
* Fake companies
* Fake job titles
* Fake certifications
* Fake achievements
* Fake skills
* Fake educational qualifications
* Fake professional experience
* Fake social or professional links

If information is missing, omit it rather than inventing it.

---

## Existing Project Protection

When working inside an existing project:

* Inspect the existing structure first.
* Preserve working functionality.
* Do not unnecessarily replace existing files.
* Do not delete important files.
* Reuse existing components where appropriate.
* Make targeted modifications.
* Explain significant structural changes before applying them.

---

## Portfolio Review

After generating the portfolio, perform a review covering:

* Content accuracy
* UI/UX
* Visual hierarchy
* Typography
* Spacing
* Navigation
* Responsiveness
* Accessibility
* Project presentation
* Mobile layout
* HTML quality
* CSS quality
* JavaScript quality
* Broken links
* Missing assets
* Button functionality
* Browser console errors

Identify the five most important improvements.

Do not apply improvements immediately.

Present the recommendations to the user and wait for approval.

---

## Improvement Process

After the user approves the improvements:

1. Apply the approved improvements.
2. Preserve existing functionality.
3. Do not invent new information.
4. Avoid unnecessary rewrites.
5. Review the modified files.
6. Test the portfolio again.

---

## Final Validation

Before considering the portfolio complete, verify:

* The website loads correctly.
* All relevant sections are present.
* Content matches the verified CV.
* Navigation works.
* Buttons work.
* Professional links work.
* Images and assets load correctly.
* No important files were accidentally removed.
* The website is responsive.
* The layout works on desktop, tablet, and mobile.
* No obvious accessibility issues remain.
* No unsupported information has been added.
* No obvious broken links or missing assets remain.
* No unexpected browser console errors remain.

---

## User Approval Rules

The user must remain in control of significant changes.

Before making implementation changes:

1. Analyze the available information.
2. Present the extracted CV information.
3. Request verification.
4. Create an implementation plan.
5. Present the plan.
6. Wait for approval.
7. Implement the approved plan.

Before applying review improvements:

1. Review the portfolio.
2. Identify important improvements.
3. Present the improvements.
4. Wait for approval.
5. Apply the approved improvements.
6. Test the result.

Do not blindly make significant changes without user approval.

---

## Expected Outcome

The final result should be a professional, responsive personal portfolio website created from verified CV information.

The portfolio should accurately represent the user's real education, skills, projects, experience, achievements, certifications, activities, and professional links without inventing information.
